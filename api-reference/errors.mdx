When the FSS Measurement API cannot fulfill a request, it returns a JSON error body alongside an appropriate HTTP status code. Understanding the error format and common failure scenarios lets you build integrations that recover gracefully rather than surfacing raw API messages to end users.

## Error response format

All error responses share a consistent JSON shape:

```json
{
  "message": "Human-readable error message",
  "errors": {
    "field_name": [
      "Specific validation error for this field"
    ]
  },
  "status": 422
}
```

The `errors` object is only present on `422 Unprocessable Entity` responses. For all other error codes, the response body contains only `message` and `status`.

## HTTP status codes

### 4xx client errors

| Code | Status | Description |
|---|---|---|
| `400` | Bad Request | Invalid request format or parameters |
| `401` | Unauthorized | Missing or invalid authentication token |
| `403` | Forbidden | Valid token but insufficient permissions or subscription required |
| `404` | Not Found | The requested resource does not exist |
| `422` | Unprocessable Entity | One or more request body fields failed validation |
| `429` | Too Many Requests | You have exceeded the rate limit |

### 5xx server errors

| Code | Status | Description |
|---|---|---|
| `500` | Internal Server Error | An unexpected error occurred on the server |
| `503` | Service Unavailable | The API is temporarily unavailable |

## Common error scenarios

<AccordionGroup>
  <Accordion title="401 — Missing token">
    **Error response:**

    ```json
    {
      "message": "Unauthenticated.",
      "status": 401
    }
    ```

    **Solution:**
    - Include the `Authorization: Bearer {api_token}` header on every authenticated request.
    - Verify you are using the token returned from `/user/signin` or `/user/signup`.
    - If the token is missing from storage, prompt the user to sign in again.
  </Accordion>

  <Accordion title="401 — Invalid token">
    **Error response:**

    ```json
    {
      "message": "Invalid authentication token.",
      "status": 401
    }
    ```

    **Solution:**
    - The token may have been revoked or invalidated (for example, the user changed their password).
    - Clear the stored token and redirect the user to the sign-in flow to obtain a new one.
  </Accordion>

  <Accordion title="403 — Subscription required">
    **Error response:**

    ```json
    {
      "message": "Active subscription required to access this resource.",
      "status": 403
    }
    ```

    **Solution:**
    - Check the user's current plan via `GET /transactions/get_user_current_plan`.
    - If no active subscription exists, direct the user to `/transactions/init-payment` to subscribe.
    - If you believe a subscription should be active, contact support.
  </Accordion>

  <Accordion title="422 — Validation failed">
    **Error response:**

    ```json
    {
      "message": "The given data was invalid.",
      "errors": {
        "email": [
          "The email field is required."
        ],
        "password": [
          "The password must be at least 8 characters."
        ]
      },
      "status": 422
    }
    ```

    **Solution:**
    - Inspect each key in the `errors` object to identify which fields failed and why.
    - Fix the values in your request body and retry.
    - Validate data client-side before sending to avoid unnecessary round trips.
  </Accordion>

  <Accordion title="429 — Rate limited">
    **Error response:**

    ```json
    {
      "message": "Too many requests. Please try again later.",
      "status": 429
    }
    ```

    **Response headers:**

    ```
    X-RateLimit-Limit: 60
    X-RateLimit-Remaining: 0
    Retry-After: 60
    ```

    **Solution:**
    - Read the `Retry-After` header value and wait that many seconds before retrying.
    - Implement exponential backoff so successive retries space out further.
    - Cache GET responses and batch write operations to reduce total request volume.
  </Accordion>

  <Accordion title="404 — Not found">
    **Error response:**

    ```json
    {
      "message": "Resource not found.",
      "status": 404
    }
    ```

    **Solution:**
    - Verify the resource ID in the URL path is correct.
    - Confirm the resource has not been deleted.
    - Ensure the authenticated user has permission to access the resource.
  </Accordion>
</AccordionGroup>

## Error handling best practices

<CardGroup cols={2}>
  <Card title="Retry logic" icon="rotate">
    Apply exponential backoff for `429` and `5xx` responses. Start with a 1-second delay and double it on each subsequent retry, up to a maximum of three attempts.
  </Card>
  <Card title="Logging" icon="file-lines">
    Log the full error response body — including `status`, `message`, and `errors` — alongside the request URL and method to aid debugging and monitoring.
  </Card>
  <Card title="User feedback" icon="message">
    Surface the human-readable `message` field to your users rather than a generic error string. For `422` errors, map the `errors` keys back to your form inputs.
  </Card>
  <Card title="Validation" icon="check">
    Validate required fields, data types, and formats before sending a request. This eliminates avoidable `422` round trips and improves perceived responsiveness.
  </Card>
</CardGroup>

## Code examples

The following examples demonstrate a retry-with-backoff wrapper in JavaScript, Python, and PHP:

<CodeGroup>

```javascript JavaScript
async function makeAPIRequest(url, options, maxRetries = 3) {
  let retryDelay = 1000;

  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, options);
    const data = await response.json();

    if (response.status === 429) {
      const retryAfter = parseInt(response.headers.get('Retry-After') ?? '60', 10);
      console.warn(`Rate limited. Retrying after ${retryAfter}s...`);
      await new Promise((resolve) => setTimeout(resolve, retryAfter * 1000));
      continue;
    }

    if (!response.ok) {
      switch (response.status) {
        case 401:
          throw new Error('Authentication required — please sign in again.');
        case 403:
          throw new Error('Active subscription required.');
        case 422:
          console.error('Validation errors:', data.errors);
          throw new Error(data.message);
        default:
          if (response.status >= 500 && attempt < maxRetries - 1) {
            await new Promise((resolve) => setTimeout(resolve, retryDelay));
            retryDelay *= 2;
            continue;
          }
          throw new Error(data.message ?? 'Unexpected API error.');
      }
    }

    return data;
  }

  throw new Error('Maximum retries exceeded.');
}
```

```python Python
import time
import requests

def make_api_request(url, method="GET", max_retries=3, **kwargs):
    retry_delay = 1

    for attempt in range(max_retries):
        response = requests.request(method, url, **kwargs)

        if response.status_code == 429:
            retry_after = int(response.headers.get("Retry-After", 60))
            print(f"Rate limited. Retrying after {retry_after}s...")
            time.sleep(retry_after)
            continue

        data = response.json()

        if not response.ok:
            if response.status_code == 401:
                raise Exception("Authentication required — please sign in again.")
            elif response.status_code == 403:
                raise Exception("Active subscription required.")
            elif response.status_code == 422:
                raise Exception(f"Validation errors: {data.get('errors')}")
            elif response.status_code >= 500 and attempt < max_retries - 1:
                time.sleep(retry_delay * (2 ** attempt))
                continue
            else:
                raise Exception(data.get("message", "Unexpected API error."))

        return data

    raise Exception("Maximum retries exceeded.")
```

```php PHP
<?php

function makeAPIRequest(string $url, string $method = 'GET', array $payload = [], int $maxRetries = 3): array {
    $retryDelay = 1;

    for ($attempt = 0; $attempt < $maxRetries; $attempt++) {
        $ch = curl_init($url);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_CUSTOMREQUEST  => $method,
            CURLOPT_HEADER         => true,
        ]);

        if (!empty($payload)) {
            curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($payload));
        }

        $raw      = curl_exec($ch);
        $headerSz = curl_getinfo($ch, CURLINFO_HEADER_SIZE);
        $status   = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        $headers  = substr($raw, 0, $headerSz);
        $data     = json_decode(substr($raw, $headerSz), true);
        curl_close($ch);

        if ($status === 429) {
            preg_match('/Retry-After:\s*(\d+)/i', $headers, $m);
            $wait = (int)($m[1] ?? 60);
            error_log("Rate limited. Retrying after {$wait}s...");
            sleep($wait);
            continue;
        }

        if ($status >= 400) {
            switch ($status) {
                case 401:
                    throw new \RuntimeException('Authentication required — please sign in again.');
                case 403:
                    throw new \RuntimeException('Active subscription required.');
                case 422:
                    throw new \RuntimeException('Validation errors: ' . json_encode($data['errors'] ?? []));
                default:
                    if ($status >= 500 && $attempt < $maxRetries - 1) {
                        sleep($retryDelay * (2 ** $attempt));
                        continue 2;
                    }
                    throw new \RuntimeException($data['message'] ?? 'Unexpected API error.');
            }
        }

        return $data;
    }

    throw new \RuntimeException('Maximum retries exceeded.');
}
```
